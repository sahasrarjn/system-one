# tiny/ — a System One model from scratch

Start here. ~430 lines, no GPU, trains in about 40 seconds.

```bash
python -m tiny.run
```

## Why synthetic data

The task is generated by a process we control, so Bayes' rule gives the
**exact** `P(category | document)` in closed form. That buys two things real
data cannot:

- a calibration target that is *truth*, not an estimate
- a known accuracy **ceiling**, so "the model is bad" is distinguishable from
  "the task is genuinely ambiguous"

At `signal=0.20` the ceiling is **0.687**. A model scoring 0.69 is not
mediocre; it is optimal.

## The lesson

Same architecture, same loss, two different targets:

| | hard labels | soft targets |
|---|---|---|
| accuracy | 0.654 | **0.687** (= Bayes ceiling) |
| ECE | 0.097 | **0.039** |
| L1 to true posterior | 0.317 | **0.091** |

Training on the sampled label throws away the information that the label was
*uncertain*. Training on the distribution keeps it. Cross-entropy on hard
labels is asymptotically fine — the Bayes posterior minimises it — but with
finite data and enough capacity the model drives train confidence to 1 and
becomes overconfident. That is the whole argument for distilling teacher
*distributions* rather than teacher argmaxes.

## Where to read

- `data.py` — the generative process and the exact posterior
- `model.py` — hand-written transformer. The block mask is one line in
  `Attention.forward`; everything else is a standard encoder
- `run.py` — training, the ablation, and the Jev property demos

Scale-up lives in `systemone/` (Qwen3-0.6B, real corpora).
